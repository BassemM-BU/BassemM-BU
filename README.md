### 👋 About me

I build machine learning systems that have to work on **real hardware with messy data**.

My path into computer science runs through mechanical engineering and eight years running a truck workshop with 30+ technicians across the Middle East and Africa. That work taught me to trust measurements over assumptions, find root causes, and write things down. I now bring the same habits to ML: check the data first, test it, and be honest about what the results actually show.

Today I'm a **Machine Learning Engineer Intern at VCycene Inc.**, working on a reinforcement learning study that controls composting machines from live sensor data. In parallel, I'm completing the **Online M.S. in Computer Science & Artificial Intelligence at Boston University** to build the computer science foundations underneath the ML work.

---

### 🔭 What I'm working on now

- **Offline reinforcement learning in the real world.** I'm learning control policies from logged sensor decisions and scoring them with off-policy evaluation before they ever touch a machine.
- **Systems programming in C.** Pointers, memory layout, the heap, bit manipulation, and building my own pool allocator (BU CX651).
- **The math behind ML.** Linear algebra, probability, and optimization, implemented from first principles in Python (BU DX601).

### 🧩 Problems that interest me

- **ML that touches the physical world.** Sensors, machines, and control loops, where a wrong decision has a real cost.
- **Trustworthy evaluation.** How do you know a model is better *before* you deploy it? I care about honest baselines, leakage checks, and saying "within noise" when that's the truth.
- **Data you can rely on.** Pipelines that recover from bad bytes, tests that block label leakage, and schemas that don't drift.
- **Turning research into tools people use.** Dashboards, run guides, and scoring pages that make an ML study usable by the whole team.
